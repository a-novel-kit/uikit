# Layout & shape

Use public spacing, radius, control, border, focus, and motion tokens in component styles.

## Spacing

The spacing scale starts at `--space-base` and exposes named steps. Space inside and between elements
repeats a few of them: 4, 8, 12, 16, 24 and 32 pixels (`--space-{1,2,3,4,6,8}`), with 48 and 64
(`--space-{12,16}`) for page layout. The in-between steps only size dense details, such as a badge.

Pick a gap by its role. A component that owns the role, such as `Stack` or `FormActions`, already
applies it.

| Role                                              | Token                                           | Size        |
| ------------------------------------------------- | ----------------------------------------------- | ----------- |
| Links of one navigation group                     | none, as `NavList` sets                         | 0 px        |
| Lines of one item, such as a name and its details | `--space-1`                                     | 4 px        |
| Icon and its label, compact inline items          | `--space-2`                                     | 8 px        |
| Navigation groups, either side of a `Separator`   | `--space-2`                                     | 8 px        |
| Buttons in a group                                | `--space-3`, as `ActionGroup` sets              | 12 px       |
| A heading and the content it names                | `--space-3`                                     | 12 px       |
| Islands side by side                              | `--layout-island-gap`                           | 12 px       |
| Fields, list rows and stacked items               | `--space-4`, as `Stack` sets by default         | 16 px       |
| Inside an island                                  | `--space-4`, as `Card` sets by default          | 16 px       |
| Sections of a page or a dialog                    | `--space-6`                                     | 24 px       |
| A form's actions, below its last field            | `--space-8`, as `FormActions` sets in a `Stack` | 32 px       |
| A navigation rail's top and bottom groups         | `--space-8`, so they never run together         | 32 px       |
| A page's top and bottom                           | `--space-6` and `--space-12`                    | 24, 48 px   |
| A page's sides                                    | `--layout-gutter`                               | 16 to 32 px |
| Dense details, such as a badge or a check mark    | `--space-1-5`, `--space-5`                      | 6, 20 px    |

A value outside this table is an exception: it sits beside a comment naming its reason.

</div>

## Layout

Widths come from the layout tokens, never from a hand-picked size.

| Token                       | Use                                                      | Size      |
| --------------------------- | -------------------------------------------------------- | --------- |
| `--layout-container-xs`     | Compact dialogs, `Dialog size="sm"`                      | 26.67 rem |
| `--layout-container-sm`     | Forms, settings pages and dialogs, `Container size="sm"` | 40 rem    |
| `--layout-container-md`     | Wider pages, `Container size="md"`                       | 64 rem    |
| `--layout-container-lg`     | Full application pages, `Container`'s default            | 80 rem    |
| `--layout-readable-measure` | Running text, `Container size="readable"` and `Prose`    | 68 ch     |
| `--layout-sidebar`          | A navigation rail or a split pane's side                 | 15.28 rem |

Every page fills the viewport's height with `100dvb`, and the root keeps `min-inline-size: 20rem`:
WCAG 1.4.10 reflows content down to 320 CSS pixels, and a narrower window scrolls instead.

## Proportion

Use smaller ratios for dense interface details and reserve the major ratio for page-level hierarchy.

    </div>
  ))}
</div>

## Surfaces

Group related content with spacing first. Use a borderless island when a region needs its own visual
plane. `--shadow-{sm,md,lg}` give an island a hairline ring and a soft shadow; its face stays flat.
`--shadow-floating` reaches every side, for a surface that floats over other islands. A
well, such as a field, darkens the surface it sits on, so it keeps that surface's tone. Fields sit inside an
island and need no border; only focus and errors outline them.

<div className="surface-demo">
  <section className="surface-group">
    <strong>Invisible group</strong>
    <span>Primary content and related sections</span>
  </section>
  <section className="surface-island surface-island--subtle">
    <strong>Subtle island</strong>
    <span>Supporting groups and passive regions</span>
  </section>
  <section className="surface-island surface-island--strong">
    <strong>Strong island</strong>
    <span>Floating tools, navigation, and overlays</span>
  </section>
</div>

## Control and interaction metrics

| Contract       | Tokens                                                  |
| -------------- | ------------------------------------------------------- |
| Control height | `--control-height-{sm,md,lg}`, one step taller on touch |
| Icon size      | `--icon-size-{sm,md,lg}`: 16, 20 and 24 pixels          |
| Nested control | `--control-height-nested`, inside a medium field        |
| Border         | `--border-width-thin`                                   |
| Focus          | `--focus-ring-{width,offset}` and `--color-focus-ring`  |
| Motion         | `--duration-{fast,normal}` and `--easing-standard`      |
| Disabled state | `--opacity-disabled`                                    |

The [Button](?path=/docs/components-button--documentation) stories show these tokens on an interactive
control.
