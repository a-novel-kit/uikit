# Upgrading to v0.3.0

UIKit stateful components now render state supplied by one external controller. Default reactive controllers preserve standard interactive behavior, while application and Storybook callers can provide another implementation of the same contract.

## Do I need to act?

**Required** — migrate every stateful UIKit component from bindable state props and change callbacks to its `controller` prop.

## Create controllers outside components

Create a controller in the calling component or route controller, then pass it to the UIKit component. Do not recreate a controller from markup or a reactive expression.

```svelte
<!-- before -->
<script lang="ts">
  let open = $state(false);
</script>

<Button onclick={() => (open = true)}>Open</Button>
<Dialog bind:open title="Account">...</Dialog>
```

```svelte
<!-- after -->
<script lang="ts">
  import { Button, Dialog, createOpenController } from "@a-novel-kit/uikit";

  const dialogController = createOpenController();
</script>

<Button onclick={() => dialogController.open()}>Open</Button>
<Dialog controller={dialogController} title="Account">...</Dialog>
```

The default controller factories are:

| State shape                        | Factory                    | Components                                                                  |
| ---------------------------------- | -------------------------- | --------------------------------------------------------------------------- |
| Open or closed                     | `createOpenController`     | `AccordionItem`, `ActionMenu`, `Dialog`, `Disclosure`, `Popover`, `Tooltip` |
| Checked                            | `createCheckedController`  | `Checkbox`, `Switch`                                                        |
| Pressed                            | `createPressedController`  | `ToggleButton`, `ToolbarToggleButton`                                       |
| One value                          | `createValueController`    | `RadioGroup`, `Slider`, `Tabs`                                              |
| Value and popup visibility         | `createSelectController`   | `Select`                                                                    |
| Value, query, and popup visibility | `createComboboxController` | `Combobox`                                                                  |

Callbacks moved to factory options. For example, replace `onValueChange` on `Select` with `createSelectController({ onValueChange })`.

## Provide a custom controller when needed

Each component exports its controller type. A custom controller may accept, transform, or reject a requested transition, but its `state` must remain reactive when it changes.

```svelte
<script lang="ts">
  import { Dialog, type DialogController } from "@a-novel-kit/uikit";

  const pinnedDialog: DialogController = {
    state: { open: true },
    open() {},
    close() {},
    toggle() {},
  };
</script>

<Dialog controller={pinnedDialog} title="Pinned preview">...</Dialog>
```

This fixed controller is useful in Storybook when a close gesture must not change the rendered story state. Production controllers should expose reactive state and implement the same semantic methods without accessing the DOM.

## Notes

Components still own accessibility attributes, native event translation, focus movement, measurements, and element references. Controllers own rendered state and its transitions only.
